# SciHub 项目检查与 v1.0.3 修复报告

检查日期：2026-10-08。检查对象：静态前端、Service Worker、完整 SQL 参考及迁移、四个 Supabase Edge Functions、发布脚本与文档。

## 作为电子实验记录本的成熟度

现阶段适合个人科研记录与实验执行。已有完整的「导入方案 → 校对步骤 → 启动实验 → 记录数据/媒体 → 完成生成日志 → 检索/导出」路径。尚不足以作为具有签署、审批、不可变审计与长期归档保障的实验室级 ELN。

| 已有能力 | 实际边界 |
| --- | --- |
| 邮箱/用户名/电话登录、注册、账户信息、改密码 | 各账号隔离；没有团队成员角色与审批 |
| 科研记录新建、编辑、删除、标签、类别、搜索和 CSV | 没有回收站、完整修订历史；大量数据缺少分页 |
| DOCX 方案导入、AI/规则解析、字段类型、步骤排序、重新解析和快照恢复 | AI 输出需人工校对；进行中实验的方案同步不是整组事务 |
| 按步骤填写、备注、照片/视频、自动保存、多端 Realtime | 保存失败保留当前页输入，但没有持久化离线编辑草稿 |
| 实验关联、首页分组、日历、待办和计时、热解程序计算器 | 计时为界面估算；日历依赖当前状态和最近时间戳，不能重建完整历史 |
| 完成后生成实验日志、Word 导出关联实验快照 | 已完成只读由前端约束；视频导出列名称，未嵌入视频 |
| PWA、资源缓存、版本检查与 GitHub Pages | 离线页面缓存不等同离线数据同步 |

## 已修复的问题

1. **输入丢失与错误实验写入**：按步骤防抖、同一步串行保存；网络失败保留 dirty 状态；导航/退出/更新等待保存；写入用步骤自己的账号与实验 ID。
2. **并发覆盖和失败却推进**：步骤写入检查 `updated_at`，他端更改不覆盖本地输入；保存失败不进入下一步、不提示上传成功。
3. **方案保存与完成实验缺乏事务**：获用户明确授权后新增迁移 `20261008090000_atomic_experiment_writes.sql`，分别原子保存方案/步骤/版本日志，以及生成日志/完成状态；完成请求幂等。同步更新 schema 参考，未修改已应用基线。
4. **方案改动导致数据串工序**：步骤名称/顺序改变拒绝按位置迁移；重名步骤内容变化拒绝对应；已有数值单位改变拒绝自动迁移；保留历史字段和零值。
5. **关联误判与分组不稳定**：比较说明、注意事项、热解、时长、字段与数字条件；字段配对一对一；选择变化使旧检测失效；用无向连通组件分组。数据库无目标合并点字段，因此新关联要求双方合并点序号一致。
6. **Word/CSV 导出风险**：导出不依赖活动编辑器全局对象；各关联实验保留各自完整快照与媒体；丢图明确标注、非兼容图片转 PNG、XML 控制字符清除；CSV 处理公式注入。
7. **异步页面与认证风险**：延迟 auth 回调内 SDK 调用避免内部锁；账号变化拒绝旧查询结果；主页与实验加载增加请求序列；已完成媒体不再可拖动编辑。
8. **AI 代理边界**：四个函数先验证真实注册用户，再访问收费上游；限制请求 256 KiB、认证超时 10 秒、上游超时 45 秒；校验部分 AI 输出结构/步骤数/配对。
9. **缓存和发布脚本**：只处理 SciHub 缓存；失败响应不缓存、离线 JS 不返回 HTML；发布脚本禁止自动全量暂存、缺 Node 不跳过验证，检查 master/远程、版本与疑似凭据。
10. **其他修复**：注册电话恢复选填；首页显示全部进行中实验，日历包含跨月实验；媒体移除先保存数据库引用、成功后处理 Storage；启动失败保留准备记录，不显示无步骤的运行实验。

## 代码债务判断

存在明显债务，尤其 `experiment.js` 和 `app.js` 同时管理查询、状态、DOM、导出与交互，跨函数共享可变对象很多，异步边界难以追踪。闲置 AI 进度/待办代码和重复关联弹窗增加维护成本，本次已移除；保存规则抽出 `data-safety.js` 并建立故障回归。未进行全量框架迁移，避免在数据修复中同时引入大规模架构变化。

下一步应逐步拆出数据访问、实验状态、方案编辑、媒体和导出模块，增加明确的数据契约，再考虑 TypeScript。拆分应以现有回归保证行为一致。

## 尚存风险及需要独立设计的数据库变更

| 优先级 | 风险 | 建议 |
| --- | --- | --- |
| 高 | `research_lookup_login_email` 向匿名调用者返回匹配邮箱，存在账号枚举/隐私风险 | 改成服务端登录入口，限速、统一错误；涉及现有登录行为及新数据库授权，本次未改 |
| 高 | 行级 RLS 只校验本行 owner，未完整约束跨表父子 owner 一致性 | 增加组合外键/策略，先检查现有数据，不应未经批准改库 |
| 高 | 已完成只读未在数据库强制；无不可变审计事件、签署或修订流程 | 增加服务器约束、版本化快照及追加式审计 |
| 中 | 进行中实验方案同步与多实验关联仍为多次请求 | 设计新的事务接口；目前有单行冲突检查，仍可能部分成功 |
| 中 | AI 无持久化账号配额/限速 | 服务端额度与请求速率控制；现认证、大小和超时限制不能代替限额 |
| 中 | 没有离线草稿、回收站、备份恢复；准备失败可能保留 aborted 记录及孤立文件 | 先设计恢复与可审阅清理流程，不自动删除 |
| 中 | `plan_steps` 未加入当前 Realtime 发布 | 方案变化实时提示不能保证；可先增加重新聚焦检查，增加发布表需额外数据库授权 |
| 中 | 当前时间戳并非逐次事件记录，大数据查询缺分页，外部 CDN 仍是依赖 | 审计事件、分页和依赖固定版本/本地化 |

以上问题不属于此次「新增两个事务接口」的授权范围，未擅自增加新的数据库结构。

## 建议的功能路线

1. **先保证科研数据可信**：修订历史、追加式审计、完成锁定与更正申请、备份还原、回收站、离线草稿与冲突处理。
2. **再建立科研对象关系**：样品编号与流转、试剂批号/库存、仪器和校准信息、原始 TXT/CSV/XLSX/PDF 附件、文件校验值、实验到表征结果的关联。
3. **再支持实验室协作**：项目/课题权限、共享模板、见证/审批与电子签署、实验预约、可靠通知。
4. **分析与写作辅助**：电化学数据导入、单位与有效数字校验、结构化表征分析、出版图导出、引用管理和 PDF 归档。AI 建议需保留来源和人工确认。
