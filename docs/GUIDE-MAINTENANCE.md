# 教程维护与发布

`docs/user-guide.source.cjs` 是唯一内容源。`node tools/build-guide.cjs` 生成 GitHub 可读的 `docs/USER-GUIDE.md` 和网站的 `guide.html`。教程内容不需要账号，不读取科研数据，也不调用 AI。

网站教程通过 `index.html#guide` 在软件外壳中显示，复用固定顶部栏、工具和账号菜单。`guide.html` 保留完整静态内容供缓存和无 JavaScript 阅读；已有教程链接及流程锚点进入外壳中的相同流程。`guide.js` 的挂载只初始化一次，样式限定在 `.guide-page` 内，避免影响软件表单。软件外壳沿用正常认证流程；有登录会话时仍会加载该账号的工作台数据。

教程首页直接显示“使用教程”，提供版本、目录和操作入口。写作规范、技术选型和符合性说明只在本维护文档中记录，不作为网站或 GitHub 使用教程的开场内容。用户可见的命名遵循 `AGENTS.md` 的发行版文案规则；必要的输入格式、单位和操作影响仍须明确。

## 每次功能更新

1. 对照新旧界面与数据库行为，核对所有受影响流程。补充新入口，移除失效指令；保留旧数据适配流程和真实功能边界。
2. 修改源文件中的中英步骤、开始条件、操作影响、结果、故障处理和术语。按钮中文须与实际界面一致。英文使用命令式、主动语态、一个明确操作及一致术语；操作句最多 20 词，说明句最多 25 词，不使用缩约词。技术名词、单位及原样 UI 文本属于领域术语。
3. 按项目版本规则更新软件版本，同时手动同步教程源的 `version` 与 `updated`。不以自动替换版本号代替内容审阅。
4. 完成实际功能核对后，运行 `node tools/build-guide.cjs --review`。它记录当时功能文件和教程源的 SHA-256，并生成两份产物。SHA-256 忽略 CRLF/LF 差异。
5. 运行 `node tools/build-guide.cjs --check`、发布检查、适用的回归及浏览器检查。生成器拒绝过期版本、双语缺失、重复流程 ID、超长英文句子、过期审阅记录及不同步的产物。
6. 只暂存已核对的文件，运行 `node tools/check-release.cjs --staged`，检查暂存差异后提交、推送。教程与功能必须在同一提交发布，不能先公开不对应的说明。
7. 检查 GitHub Pages 与 Supabase 结果，并验证线上教程、功能和版本相符。已打开页面每五分钟检查版本；离线用户重连并更新后读取新版本，不承诺在离线页面即时替换内容。

## 推送检查

仓库提供 `.githooks/pre-push`。当前维护工作区启用该钩子，推送前运行教程与软件发布检查。新工作区可在确认没有现有自定义钩子后运行 `git config --local core.hooksPath .githooks`。

`tools/sync.sh` 也调用暂存发布检查。直接绕过本地钩子不代表验证通过，维护者仍必须遵守 AGENTS.md。本地检查不是 GitHub 分支保护；仓库当前凭据没有 `workflow` scope，本次不新增 GitHub Actions 工作流。

## ASD-STE100 范围与复核

参考 [ASD-STE100 官方 FAQ](https://www.asd-ste100.org/STE_faq.html) 和 [官方标准说明](https://www.asd-ste100.org/about_STE.html)。官网当前标示 Issue 9。STE 包含写作规则和受控词典；它允许按规则使用领域技术名词和技术动词。

本教程采用英文简明技术写作原则，中文是对应翻译。词数、缩约词和结构检查仅覆盖可自动检验的部分，不检查全部词典批准含义、词性或所有规则。当前未完成完整词典及独立人工符合性审核，不能标称正式认证或完全符合 ASD-STE100。

已废弃且无界面入口的函数不作为用户功能编写；维护/部署接口不混入实验操作者流程。教程不包含真实账号、真实实验内容或凭据。
